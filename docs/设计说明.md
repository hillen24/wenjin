# 问津 · 设计说明 v2.0

> 版本：v0.4（2026-10-24）
> 定位一句话：**哲学思维训练场**——不是词典，不是课程，是每天真拿来练的。
> 部署形态：局域网自托管（家里常驻主机 + 手机/电脑双端），无云端依赖。

---

## 一、产品原则（做任何取舍时回来对这四个）

1. **追问优先于答案**：AI 默认不当百科，先问再讲，讲也带着问题讲
2. **每次使用必须落到"可操作的一步"**：伴读结束有一个行动项，格物结束有一个下一步——不许只留在"想通了"
3. **数据在家**：断网全功能可用，联网只是模型更强
4. **克制**：MVP 只做通三个闭环，别的全部砍到 v0.2 之后

## 三、核心用户旅程（三个闭环）

**旅程 A · 伴读者（治"读不懂"）**
读《爱比克泰德》开篇 → 划到"有些事物在我们能力之内"不解 → 选"讲解" → AI 分层讲清 → 顺手选"追问"被问三轮 → 三个概念节点点亮 → 收藏到"我的困惑"

**旅程 B · 焦虑者（治"用不上"）**
睡前打开格物 → 输入今天烦扰（如"模考排名下滑"）→ AI 用控制二分法追问三轮 → 生成格物卡（可控项/不可控项/下一步行动）→ 次日晨间推送回看 → 一周后格物卡沉淀成"我的斯多葛练习记录"

**旅程 C · 收集者（治"学孤立"）**
刷星图 → 发现暗节点"庖丁解牛" → 读条目 → 点亮 → 解锁关联节点"知行合一" → 顺手在庄子伴读页划一句"以无厚入有间"求证

## 四、核心流程详设

### 4.1 伴读流程

```
打开原文 → 选中任意片段 → 弹出三问工具条
  ├─ 讲讲这段  → 讲解技能（分层：人话版/学术版切换）
  ├─ 我没懂，引导我 → 追问技能（苏格拉底六式，最多 4 轮，答对即收）
  └─ 这在反驳谁 → 格义技能 + 图谱关联（返回立场图谱 + 相关节点）
→ 回答末尾必带：①关联概念（一键点亮）②一个"落到今天"的问题
```

硬规则：**每次 AI 回答必须带一个可点亮的节点或一个行动问题**，否则视为残次输出（prompt 层强制）。

### 4.2 格物流程（日常格物 · 晚间）

```
① 输入"今天什么烦扰了你"（自由文本）
② AI 追问 2-3 轮（按所选方法论 SOP 走，默认 A1 控制二分法）
③ 二分归类：用户把烦扰拆成"可控 / 不可控"两列（拖拽）
④ 生成格物卡：可控项→下一步最小行动；不可控项→"愿意其发生"一句话
⑤ 晨间（8:00）推送昨日格物卡回看
```

追问轮数上限 3，到点必须收——**哲学 App 不制造新的焦虑**。

### 4.3 星图流程

- 27 节点 / 21 边，三类关系视觉区分：**继承（实线）/ 反对（红虚线）/ 提出（点线）**
- 节点状态：已点亮（实心）/ 已读未亮（半透）/ 暗（盲区）
- 点亮来源：伴读关联、方法论条目阅读、格物追问触达
- 盲区检测：按流派分区算点亮率，低于 40% 的星区标灰——"你的古希腊区还黑着"

## 五、技术选型（全部贴现成家当）

| 层 | 选型 | 理由 |
|----|------|------|
| 常驻主机 | 家里一台 PC/NAS，7×24 | 就是它当"服务器" |

| 图谱渲染 | d3-force（桌面/手机同代码降级） | 生态成熟 |
| 同步 | REST + WebSocket 推送（v0.2 实装） | v0.1 单设备也全功能 |
| 备份 | 每日 SQLite 快照 + 图谱 JSON 导出 | 家训：备份一律不删 |

## 六、数据模型（SQLite）

```sql
-- 概念节点
CREATE TABLE concepts (
  id TEXT PRIMARY KEY,            -- 'stoic-dichotomy'
  name TEXT NOT NULL,             -- '控制二分法'
  kind TEXT NOT NULL,             -- concept | figure | school | method
  school TEXT,                    -- '古希腊' '德国古典' '现代分析'...
  brief TEXT,                     -- 两句话简介
  source TEXT                     -- 出处
);
-- 关系边
CREATE TABLE edges (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  from_id TEXT NOT NULL, to_id TEXT NOT NULL,
  rel TEXT NOT NULL,              -- proposes | inherits | opposes | refines
  note TEXT                       -- '休谟的怀疑唤醒康德'
);
-- 方法论条目
CREATE TABLE entries (
  id TEXT PRIMARY KEY,            -- 'A1'
  name TEXT, category TEXT,       -- 生活指导 | 思维工具 | 论辩表达
  oneliner TEXT, sop TEXT,        -- sop: JSON 数组
  misuse TEXT, source TEXT,
  related_concepts TEXT           -- JSON 数组 of concept id
);
-- 阅读进度与批注
CREATE TABLE reading_progress (doc_id TEXT, para_idx INT, scroll_pos REAL, updated_at TEXT);
CREATE TABLE annotations (id INTEGER PRIMARY KEY, doc_id TEXT, quote TEXT,
  skill TEXT, ai_reply TEXT, created_at TEXT);
-- 格物会话
CREATE TABLE gewu_sessions (
  id INTEGER PRIMARY KEY,
  date TEXT, entry_id TEXT,       -- 当晚用的方法论条目
  bother TEXT,                    -- 用户输入的烦扰
  dialogue TEXT,                  -- 追问全记录 JSON
  controllable TEXT, uncontrollable TEXT,   -- 二分结果 JSON
  next_action TEXT,               -- 下一步最小行动
  done INTEGER DEFAULT 0
);
-- 用户点亮状态
CREATE TABLE lit_nodes (concept_id TEXT, lit_at TEXT, via TEXT);  -- via: 伴读/条目/格物
```

## 七、AI 技能层设计

### 7.1 调用协议

```
POST /api/skill/{skill}
{ skill: "追问" | "讲解" | "批改 | 推演 | 格义 | 裁判",
  context: { doc_id?, quote?, entry_id?, history? },
  user_input: "..." }
→ { reply, lit_nodes: [...], action_prompt: "..." }   # 后两个字段协议强制
```

### 7.2 六技能 prompt 策略

| 技能 | 人设 | 硬规则 | 输出格式 |
|------|------|--------|----------|
| 追问 | 苏格拉底，只问不答 | 一次只问一个问题；不问已知答案的问题；最多 4 轮；发现用户自己说出来了就停 | 问题 + （末轮）一句确认 |
| 讲解 | 耐心的哲学教授 | 先人话版后学术版；禁用"正如我们所知"；必须举一个生活例子 | 分层两段 + 关联节点 |
| 批改 | 严格的论证教练 | 只评论证不评人；谬误必须点名并给反例；先讲好在哪 | 亮点 / 漏洞分级 / 改写建议 |
| 推演 | 思想实验主持人 | 只推演不站队；每个立场推到极端 | 分支推演 + 代价提示 |
| 格义 | 贯通中西的译者 | 中西概念互译须标注"近似不相等" | 对照卡 + 不相等处 |
| 裁判 | 中立辩论裁判 | 按论证质量判不按立场；双方各给一条最佳时刻 | 评分维度 + 双方最佳时刻 |

### 7.3 追问技能 · 苏格拉底六式嵌入

prompt 内置六式轮盘：澄清问题 → 追问假设 → 追问证据 → 追问视角 → 追问后果 → 追问问题本身。每轮按序取一式，用户抗追问时自动跳到"追问视角"（换个眼睛看自己的立场）。

### 7.4 三级降级链（保证格物永不卡死）

```
本地 Ollama qwen2.5:7b  →  DeepSeek API  →  预置脚本（条目 SOP 固化的追问树）
```
- 断网/模型挂了，格物走预置脚本树照样完成——这是原则 3"断网全功能"的落地
- v0.1 原型即用预置脚本树 mock，真 LLM 接入只是替换最后一级

## 十一、v0.2 增补设计（2026-10-24）

### 11.1 论道（AI 哲学家人格）

- 定位：把"多哲学家人格"从追问技能的一个参数升级为独立场景——**直接找一位哲学家论道/请教**
- 首批 6 位：苏格拉底（只问不答）、爱比克泰德、康德、尼采、庄子、王阳明，各有打招呼语、3 个快捷问题、3+ 组剧本问答、人格化兜底回复
- 与星图双向联通：人物节点详情页出现"⚖ 与他论道"入口；论道记录可整场存入我的哲学书
- 技术：人格 = 系统提示词 + 人物知识卡；追问技能默认开启（苏格拉底人格本身就是追问）

### 11.2 我的哲学体系（积累成书）

- 三类沉淀源：☾ 格物卡（权重 ×2）、⚖ 论道记录、📖 伴读问答（划句 + 技能 + 回答）
- AI 梳理（mock）：序言 / 烦恼地图 / 我在用的方法（条目频次）/ 我的命题（练习句凝结）/ 疑问与对话 / 尾声叮嘱
- 成书进度按素材权重计（40 点 = 100%），阶段：萌芽 → 小册 → 逼近成稿 → 成书
- 导出 .md；全部数据可 JSON 备份/导入（家训：备份一律不删）

### 11.3 设置页（自己的 API）

- 服务商预设：本地 Ollama / DeepSeek / 硅基流动 / 自定义（OpenAI 兼容）；Key 只存本机 localStorage
- 模型路由：主力 + 兜底 + 断网自动降级预置脚本（第三级）
- 阅读与朗读：正文字号、TTS 语音/语速/连续模式
- Ollama 可真实探测 `/api/tags`；其余为模拟连接（真机版由局域网主机托管）

### 11.4 精读伴读 · 电子书化

- 书架：内置原著 + 我的书库；载入 .txt/.md（点击或拖入），按空行分段，localStorage 持久化（原型限 2MB）
- 阅读进度：点段落标记已读，书架显示"已读 x/y 段"
- TTS：浏览器 speechSynthesis 真朗读，段落级/全文连续，朗读中段落高亮跟随，不花 token、断网可用
- 自定义书籍走通用讲解链路（原型版明确告知），划句三问、存入哲学书全功能保留

### 11.5 手机端原型（`问津-手机端-v0.1.html`，97KB 单文件）

- **不做桌面版缩小，独立移动端形态**：底部 5 Tab（星河/伴读/格物/论道/我的），单手拇指区操作；桌面浏览器打开显示手机壳预览，窗口 ≤480px 或真机打开自动全屏（100dvh + safe-area）
- **星图移动化**：单指平移、双指捏合缩放（viewBox 变换）、点节点出 bottom sheet（含三入口 + 关系网），去掉拖拽节点（手机上误触多）
- **伴读移动化**：**点段落即问**，不划选（划选在手机上误触严重）；底部操作条三问 + 🔊；书架横滑书签，支持载入 .txt/.md
- **格物/论道**：全屏步骤流（5 步指示器）+ 聊天气泡 + 底部固定输入 dock
- **双端同数据**：与桌面端原型读写相同 localStorage keys（settings / materials / user books / progress / lit），直接演示“双端同数据”；真机版经局域网常驻主机同步
- 手机端独立持久化星图点亮（`wj_lit_v1`）与格物历史（`wj_gw_history_v1`），桌面端 v0.4 起补齐同样持久化

## 十二、v0.3 增补设计（2026-10-24）

### 12.1 桌面端布局重构（原型 v0.4）

- **旧问题**：header + 横向 nav + 1180px 居中内容，垂直空间浪费、视线跳跃、面板散在各 tab 内部
- **新骨架**：`sidebar（198px 墨色竖列导航）｜stage（中央视野区）｜rail（332px 右轨）`
  - 五个辅助面板组（星图详情/盲区、伴读 AI 面板、格物统计/历史、论道哲学家列表、哲学书侧栏）统一收进右轨，按 `body[data-tab]` 切换显隐
  - 方法论/设置两个 tab 无右轨，内容自动全宽
  - 星图/论道/格物/哲学书高度改 `calc(100vh - …)` 撑满视口；1180px 以下隐藏右轨，960px 以下 sidebar 收成图标条
- sidebar 底部常驻 **AI 模式状态点**（已接入 XXX / 预置脚本 AI · 待配置）

### 12.2 真 LLM 接入层（填 Key 即用）

- 统一路由 `aiCall(system, user, messages)`：OpenAI 兼容 `/chat/completions`，45s 超时，Key 走 Authorization 头
- 接入面：伴读「讲讲 / 反驳谁」（原文全文 + 选中句作上下文）、格物追问（条目 SOP + 误用注入 system prompt，三轮上限由 prompt 约束）、论道（人格 persona system prompt + 完整对话历史）、哲学书 AI 梳理（AI 执笔序言/叮嘱，`__synthOverride` 渲染）
- **三级降级**：主力模型 → 兜底 → 预置脚本树；任何一环失败静默降级并 toast 提示，功能不中断
- 六哲学家 persona 铁律（性格/自称/类比域/禁用项/回复长度），例：苏格拉底"永不直接给答案，每次回复以一个问题收尾"

### 12.3 TTS 双引擎

- **browser**：speechSynthesis，离线兜底，偏机械

### 14.3 星图 bug 根因与修复（重点教训章）

**现象**：电脑端概念星系"只能左右拖动，不能上下拖动"。

**根因（实锤）**：`svgPt()` 用 `(clientY-r.top)*540/r.height` 硬算坐标，没有补偿 SVG `preserveAspectRatio="xMidYMid meet"` 的 letterbox。星图区在中等宽度窗口下是"高瘦"形容器（实测 svg box 385x460），viewBox 内容按 scale=min(385/680,460/540)=0.587 渲染后垂直居中、上下各留约 95px 空白。此时 y 换算整体失真：无头浏览器实测垂直拖 100px，fy=488.4 而真值=522.2（旧算法偏差 79 单位，越拖越偏，最终节点被物理边界 clamp 在 [24,516] 钉死）；水平方向恰好无 letterbox（宽是瓶颈），680/r.width 恰等于 scale，所以"正常"。

**修复（三件套）**：
1. `svgPt()` 改用 `new DOMPoint(clientX,clientY).matrixTransform(svg.getScreenCTM().inverse())`——浏览器原生 CTM 自动处理 letterbox、缩放、平移，一劳永逸；
2. 拖拽从 mouse 事件升级为 **Pointer Events + setPointerCapture**——指针拖出画布不丢事件，天然统一鼠标/触摸/笔；
3. 顺手补上现代星图该有的：**滚轮以鼠标为中心缩放**（viewBox 动态 300-1500）、**空白处抓手平移**、拖动节点发光高亮。物理引擎的向心力目标与边界 clamp 全部改为跟随动态 view。

回归测试（无头 Edge 模拟 Pointer Events）：垂直/水平/向上拖动误差全部 0.00，缩放、平移、释放全部 PASS。

手机端无此 bug——它的交互模型是"平移视图"而非"拖节点"，`contentScale` 用的是相对位移（微分意义上不受 letterbox 偏移影响）。

## 十五、v2.0 双主题与苹果式质感（2026-10-24）

### 15.1 双主题：两套 token，不是滤镜反色

最省事的做法是给亮色加一个 `filter: invert()` 或者覆盖几条背景色。两种做法都被否了：

- `invert()` 会把朱砂品牌色、星图色、图片全部搞错；
- 覆盖式改色会在第三层嵌套（弹层里的卡片里的输入框）开始失效，越改越乱。

**采取的方案**：CSS 变量双集 + `data-theme` 属性驱动。

```css
:root, :root[data-theme="dark"]  { --bg:#0B0E14; --card:#131A28; --ink:#E9EDF4; ... }
:root[data-theme="light"]        { --bg:#F5F5F7; --card:#FFFFFF; --ink:#1D1D1F; ... }
```

于是主题切换等价于改一个 attribute，所有消费 token 的地方自动跟随。配套三件事：

1. **head 内联早脚本**：在 `<body>` 渲染前从 `localStorage` 读 `wj_theme` 写进 `<html data-theme>`，消除开屏白闪 / 黑闪；
2. **星图单独建一套语义色**：`--n-method` / `--n-concept` / `--star-edge` 等，dark 下是发光的青玉与朱砂，light 下压成深青与赭石。**不是反色，是重新调过明度与饱和度的两套**；
3. **`<meta name="theme-color">` 跟着切换**，手机端状态栏颜色与页面一致。

### 15.2 苹果设计语言的四件具体事

"参考苹果设计美学"不能停在形容词，落成四条硬规则：

| 规则 | 具体做法 |
|---|---|
| 层次靠投影，不靠边框 | 所有卡片用**双层**投影：`0 1px 2px rgba(0,0,0,.06)` 定形状 + `0 12px 32px -8px rgba(0,0,0,.18)` 造浮起感；边框只留 1px hairline（亮色 `rgba(0,0,0,.06)`） |
| 材质靠 vibrancy | 弹层 / 状态栏 / 底部 Tab 用 `backdrop-filter: blur(24px) saturate(180%)` + 半透明底，滚内容时能透出后面的颜色 |
| 字体走系统栈 | `-apple-system, "SF Pro SC", "PingFang SC", "Segoe UI", ...`，正文 15px/1.65，标题用 `letter-spacing:-.02em` 收紧 |
| 动效统一缓动 | 全部 `cubic-bezier(.32,.72,0,1)`（约等于 iOS 的 spring 曲线），时长 180/260/420 三档；不再有线性过渡 |

补充：亮色底色不用纯白，用苹果的 `#F5F5F7`（System Gray 6），纯白只给卡片 —— 否则整个屏幕发虚、边界消失。

### 15.3 图标系统：29 个 SVG sprite，零 emoji

emoji 的问题不是"不好看"，是**不可控**：Windows 用 Segoe UI Emoji（彩色、自带光影）、安卓用 Noto（另一套造型）、字号变化时基线还飘。一个哲学应用里飘着彩色小脸，调性直接崩。

方案：文件顶部一个 `<svg style="display:none">` 装 29 个 `<symbol id="i-xxx" viewBox="0 0 24 24">`，用在哪儿就 `<svg class="ic"><use href="#i-xxx"/></svg>`。JS 侧一个助手函数：

```js
const ic = (n) => `<svg class="ic" aria-hidden="true"><use href="#i-${n}"/></svg>`;
```

统一规格（SF Symbols 风格）：`fill:none`、`stroke:currentColor`、`stroke-width:1.8`、`stroke-linecap:round`、`stroke-linejoin:round`。于是图标自动跟随文字颜色（含主题切换、按钮 hover、禁用态），尺寸用 `1.15em` 跟随字号。

**验收方式**：遍历整个 DOM，断言不含任何 emoji 码点。实测全站清零，只剩 `←` `→` 两个非 emoji 箭头（用于关系网方向，属正常符号）。

### 15.4 API 配置重做：从"填三个框"到"拉取—选择—验证"

v1.0 的设置页只有"服务商 / BaseURL / Key / 测试连接"四个控件，模型名靠手打 —— 手打必错（`qwen2.5:7b` 打成 `qwen-2.5-7b`，然后报 404，用户以为应用坏了）。

v2.0 的流程改成四步：

1. **选服务商** → 自动带出默认 BaseURL；
2. **填 Key**；
3. **点「拉取」** → 按协议自动探两种端点：
   - OpenAI 兼容：`GET {base}/models` → 取 `data[].id`
   - Ollama：`GET {base}/api/tags` → 取 `models[].model`
   - 先试 OpenAI 协议，失败再试 Ollama 协议；都失败则保留手填入口，**不卡死流程**；
4. **点「测试连接」** → 真发一次 `chat/completions`，成功才把 `aiVerified` 置真，侧栏状态点才转绿。

配套修正的两个坑：

- **假接入**：旧 `aiLive()` 只看"配置填没填"，而 Ollama 默认不需要 Key，导致一打开就假报"已接入"。改为 `aiVerified` 门槛，且**保存任何设置都重置验证状态**（配置变了就该重测）；
- **下拉框 value 存中文名**：`<option value="本地 Ollama">` 存进 localStorage 后，一旦显示名改动就取不到配置。全部改为 `value=key`，显示名走 `label`。

### 15.5 手机端同步：星图的两个硬坑

**坑一：竖屏下星图被压成中间一条。**
`viewBox="0 0 680 540"` + `preserveAspectRatio="xMidYMid meet"`，在 392×560 的容器里缩放比 = min(392/680, 560/540) ≈ 0.577，画布只占中间 311px 高，27 个标签平均字号剩 6px，等于不可用。

修复：`initStarView()` 按容器反算 view 尺寸 —— `view.w = clamp(340, 680, w*1.12)`，让 **1 单位 ≈ 1 CSS px**，星图真正铺满而不是"居中缩小"。

**坑二：标签大量重叠。** 实测 27 个标签里 12 对以上重叠。
先试"奇数上、偶数下交错"，仍重叠（簇内节点全挤在一侧）。最终改**放射式排布** `layoutLabel(n)`：沿"远离簇心"的方向摆标签，左右按 `ux > 0.34` 切换 `text-anchor`，接近画布边缘时翻转锚点与偏移符号（贴边不截断）。结果降到 2 对重叠 + 1 处压点。

配套：标签加 `paint-order: stroke` + `stroke: var(--bg)` 2px 描边 —— 压在连线上也能读。

### 15.6 一个真实 bug：亮色下开关打开不变色

**现象**：切到白天主题后，设置页的开关拨到"开"，滑块颜色不动。

**根因**：CSS 特异性打架。亮色覆盖规则 `:root[data-theme="light"] .switch .sl` 的特异性是 (0,2,1)，而选中态规则 `.switch input:checked + .sl` 是 (0,2,0) —— 覆盖规则无条件赢，选中态永远被压掉。

**修复**：不再用亮色覆盖去改开关底色，改成 token 驱动 `--switch-off`，选中态只写一次。**教训：主题切换系统里，凡是"状态类样式"（checked/active/disabled）都不能被主题覆盖规则碰到，否则一定被打回原形。** 同理修了 tabbar 关闭态。

### 15.7 打包与启动自愈

电脑端用 electron-builder 的 `portable` 目标封成单文件 exe，手机端用 Capacitor 封 apk。两个容易漏的点：

- **Capacitor 的 `www/` 不会自动同步到 `android/app/src/main/assets/public/`** —— 改完界面必须手动 cp 过去再 build，否则打出来的 apk 里还是旧页面。验收方式：`grep -c "wj_theme"` apk 内的 index.html，应等于 2。
- **Electron 的自愈必须写在 `require('electron')` 之前**：若环境里存在 `ELECTRON_RUN_AS_NODE`（部分开发工具会设），Electron 以纯 Node 模式启动，`require('electron')` 在第一行就抛 `Cannot find module 'electron'`，整个 main.js 直接崩，便携版没有控制台，用户看到的现象就是"双击没反应"。正确写法是文件最顶部先查环境变量、删掉它、detach 重启自己、退出：

```js
if (process.env.ELECTRON_RUN_AS_NODE) {
  const env = { ...process.env };
  delete env.ELECTRON_RUN_AS_NODE;
  const args = process.argv.slice(1).filter((a) => typeof a === 'string' && a.length > 0);
  spawn(process.execPath, args, { detached: true, stdio: 'ignore', env }).unref();
  process.exit(0);
}
const { app, BrowserWindow } = require('electron');
```

（`argv` 必须过滤空值：打包态下 `process.argv[1]` 是 `undefined`，原样传进 spawn 会失败。）

- **视觉回归必须无头截图 + 人眼过**，但要先注入 `*{transition:none!important;animation:none!important}` —— 无头虚拟时间下动画不推进，否则会拍到变色中间态和淡入半透明，误判成"颜色不对"；
- **可自动化的验收就写成断言**。本轮 49 条断言跑一遍 20 秒，比手动点 12 个页面可靠得多，且改完能立刻知道有没有回归；
- **手感类的 bug（拖动、缩放、标签重叠）只能靠实测数据定标准**："12 对重叠 → 2 对"这种数字才是修完了的证据。
